RAG Simulator Beginner Guide

Learn how Operating System Resource Allocation Graphs and Deadlocks work in 2 minutes!

P1

Process (Circles)

Represents a running program or task (e.g. Chrome, Spotify, a video game). Each circle is labeled P1, P2, etc.

Active = Ready Deadlocked = Waiting / Stuck
R1 •

Resource (Rectangles)

Represents hardware or software tools (e.g. Printer, RAM, Disk, GPU). The small dots inside show how many instances (copies) exist.

1 dot = Single instance 2+ dots = Multiple copies
←

Resource → Process (Holds / Allocated)

A green solid arrow from a Resource to a Process means the process already holds and is using an instance of that resource.

R1 → P1 ("P1 holds R1")
→

Process → Resource (Requests / Waiting)

An orange dashed arrow from a Process to a Resource means the process is waiting for and requesting that resource.

P1 → R2 ("P1 requests R2")

The "Narrow Bridge" Analogy

Imagine two cars driving from opposite directions onto a narrow one-lane bridge. Car A cannot cross until Car B backs up. Car B cannot cross until Car A backs up. Neither will back up, so both are frozen forever! That is a Deadlock.

Rule 1: Single-Instance (1 copy each)

If every resource has only 1 copy, any circular loop of arrows (e.g., P1 → R2 → P2 → R1 → P1) means 100% DEADLOCK CONFIRMED. The processes will wait forever.

Rule 2: Multi-Instance (Multiple copies)

If resources have 2 or more copies, a cycle does not always mean deadlock! If an outside process finishes and returns copies to the pool, the cycle can safely unblock.
